# Conozca los términos y conceptos utilizados en Designer.

## #

|  |  |
| --- | --- |
| <b><span id="three-d-scene"></span>Escena 3D</b> | Colección de objetos y datos relacionados con la representación y animación de una visualización del espacio 3D:<ul data-preserve-html="true"> <li data-preserve-html="true">[Mallas](#mesh)</li> <li data-preserve-html="true">[Materiales](#material)</li> <li data-preserve-html="true">Cámaras</li> <li data-preserve-html="true">Luces</li> <li data-preserve-html="true">Animación</li> <li data-preserve-html="true">Simulaciones</li> <li data-preserve-html="true">...</li> </ul>Entre los [formatos de archivo populares](https://www.adobe.com/es/products/substance3d/discover/3d-files-formats.html) para almacenar escenas 3D se incluyen el [USD](#usd) de Pixar y el FBX de Autodesk. Todos los formatos de archivo no admiten todos estos componentes |

## A

|  |  |
| --- | --- |
| <b><span id="alpha"></span>canal de Alpha</b> | Cuarto canal de una imagen en color, que se suele utilizar para describir la opacidad. |
| <b><span id="ambient-occlusion"></span>oclusión de ambiente</b> | Atenuación de la luz ambiente en superficies que están menos expuestas y, por lo tanto, son más difíciles de alcanzar. |
| <b><span id="anisotropy"></span>Anisotropía</b> | La propiedad de ser dependiente de la dirección. En otras palabras, proporcionar un resultado diferente cuando se mide u observa en un eje diferente.   Los materiales anisotrópicos tienen un aspecto diferente según el lugar desde el que se observen y los filtros anisotrópicos no se aplican uniformemente en todas las direcciones. |
| <b><span id="api"></span>API</b> | Una interfaz de programación de aplicaciones (API) es una colección de funciones y procedimientos que permite a los usuarios tener acceso a las funciones y procedimientos de otra aplicación de un programa.   Una API proporciona una capa controlada y segura entre el usuario y un programa. También puede utilizar otro lenguaje de programación para facilitar la interacción con ese programa y hacer que sea más accesible.   Designer ofrece una [API de Python](../scripting/scripting.md) que proporciona acceso fácil a una amplia gama de sus capacidades para manipular datos, crear herramientas personalizadas y acelerar los flujos de trabajo. |
| <b><span id="atomic-node"></span>Nodo atómico</b> | Los pilares fundamentales de los gráficos. Todos los [nodos de instancia](#instance-node) se pueden desglosar en gráficos de nodos atómicos. Cada tipo de gráfico tiene su propio conjunto de nodos atómicos. |

## B

|  |  |
| --- | --- |
| <b><span id="baking"></span>Horneado</b> | El proceso de calcular información de un modelo 3D y almacenar los resultados en una [textura](#texture). Los datos se colocan en la textura de acuerdo con los [UV](#uv) del modelo. |
| <b><span id="base-color"></span>Color base</b> (Albedo) | Canal de un [material](#material) definido mediante el modelo [sombreado](#shader) de rugosidad metálica de PBR. Color base especifica el color de una superficie sin ninguna información de iluminación.   No debe confundirse con [Diffuse](#diffuse). |
| <b><span id="base-parameter"></span>Parámetro base</b> | Parámetro común a todos los nodos de un gráfico de Substance que calcula un [mapa de bits](#bitmap).   Entre ellos se incluyen aspectos fundamentales del mapa de bits, como su resolución ([Tamaño de salida](#output-size)) y su [profundidad de bits](#bit-depth) (Formato de salida), o cómo se calcula el mapa de bits, como el modo [mosaico](#tiling).   Los parámetros base a menudo se [heredan](#inheritance) de otros nodos anteriores o del gráfico que hospeda el nodo. |
| <b><span id="bilinear-filtering"></span>Filtrado bilineal</b> | Proceso de interpolación utilizado en la creación de imágenes de equipos cuando una [muestra de textura](#texture-sampling) no se realiza exactamente en el centro de un píxel.   Por ejemplo, esto puede ocurrir cuando se amplía una imagen. |
| <b><span id="bit-depth"></span>Profundidad de bits</b> | Número de bits utilizados para almacenar el valor de un píxel en una textura. Las profundidades de bits más altas permiten codificar más valores, lo que produce degradados más suaves.   Hay disponibles diferentes profundidades de bits en función del tipo del valor: - Los valores enteros se pueden codificar usando 8 bits (0 a 255) o 16 bits (0 a 65.535). - Los valores de coma flotante se pueden codificar usando 16 bits (+32767.9999 a -32768.0 ) o 32 bits (-3.4E+38 a +3.4E+38). Las imágenes de rango dinámico bajo utilizan valores enteros para codificar los pasos de 0 a 1. Las imágenes de alto rango dinámico utilizan valores de coma flotante para codificar valores numéricos sin procesar.   En los Substance, la profundidad de bits se controla mediante el parámetro Formato de salida. |
| <b><span id="bitmap"></span>Mapa de bits</b> | Una imagen digital. Dos tipos de imágenes son los más comunes:<ul data-preserve-html="true"> <li data-preserve-html="true">Las imágenes en escala de grises tienen un solo canal: luminancia (L);</li> <li data-preserve-html="true">Las imágenes en color tienen tres canales: rojo, verde y azul (RGB). Una cuarta puede estar presente: alfa (A), que suele utilizarse para la opacidad. Las imágenes en color en Designer siempre son RGBA.</li> </ul>  Los mapas de bits se pueden considerar como cuadrículas de valores. Cada celda de esa cuadrícula es un píxel, que es la abreviatura de &#39;elemento de imagen&#39;. Un píxel almacena un valor por canal. El tipo de ese valor depende de la [profundidad de bits](#bit-depth) del mapa de bits. |

## C

|  |  |
| --- | --- |
| <b><span id="cache"></span>Caché</b> (Memoria) | Una recopilación de datos - P.ej. [parámetros base](#base-parameter) del nodo e imágenes de salida: almacenadas en memoria para reutilizarlas.   La caché acelera enormemente los cálculos de gráficos al permitir que [Substance Engine](#substance-engine) vuelva a calcular únicamente las partes de un gráfico que han cambiado. Al ajustar conexiones y parámetros de nodos, esos cambios no afectan a todos los nodos que los preceden, por lo que no es necesario [evaluarlos](#evaluation) de nuevo para actualizar el gráfico. En su lugar, se utiliza su caché.   La caché puede tener un espacio de memoria significativo cuando se trabaja con altas resoluciones y profundidades de bits en gráficos grandes. |
| <b><span id="channel-packing"></span>empaquetado de canal</b> | Técnica de optimización en la que se empaquetan imágenes independientes en los canales de RGB (A) de una imagen de un solo color.   Por ejemplo, una textura RMA es un mapa de rugosidad (R), un mapa de metalidad (M) y un mapa de oclusión ambiental (A), todo ello empaquetado en una sola textura de color.   Otra técnica común es el empaquetado de una textura de escala de grises en el canal azul de un mapa normal, ya que el canal azul, es decir, el componente &#39;Up&#39; del vector normal, se puede volver a calcular en tiempo de ejecución.   El nodo [RGBA merge](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md) es útil para implementar esta técnica. |
| <b><span id="color-space"></span>Espacio de color</b> | Definición de cómo se representa una gama de colores. La codificación y descodificación digitales de un color específico requieren dicha definición para dar sentido a los números utilizados.   Un archivo de imagen almacena valores de color utilizando un espacio de color especificado, de modo que estos colores se puedan reproducir fielmente en una pantalla que admita ese espacio de color. Una pantalla tiene capacidades de reproducción de color específicas que le permiten admitir total o parcialmente un espacio de color determinado.   Datos sin procesar: p. ej. un mapa normal: siempre se codifica y descodifica en un espacio de color lineal, ya que estos colores no están pensados para ser visualizados y no deben aplicarse transformaciones a esos datos.   sRGB es un espacio de color muy compatible. Otros espacios de color populares son Adobe RGB, Rec. 2100 y ProPhoto RGB. |
| <b><span id="cooking"></span>Preparando </b>(<span id="compilation"></span>Compilación) | El proceso de traducir datos a otro idioma para que se puedan ejecutar de forma rápida y eficaz. Para calcular el resultado de un gráfico de Substance es necesario compilarlo primero. La compilación es parte del proceso de [evaluación](#evaluation) del gráfico.   Esta compilación se realiza en un gráfico acoplado, lo que significa que todos los [nodos de instancia](#instance-node) se &#39;reemplazan&#39; por sus gráficos de origen, de modo que queda un gráfico más grande, y ese gráfico es lo que se compila.   Un gráfico compilado no es editable. Los parámetros expuestos permanecen disponibles si son [dinámicos](#dynamic-parameter), mientras que los parámetros [estáticos](#static-parameter) están bloqueados y ocultos. |
| <b><span id="culling"></span>Sacrificio</b> | Técnica de optimización para la representación de escenas 3D que elimina la geometría de los cálculos de un procesamiento cuando no es visible.   Esto puede incluir objetos o polígonos fuera del árbol de la cámara (*recorte de árboles*), que se encuentren en el lado opuesto a la cámara (*recorte de caras traseras*) o que estén completamente ocultos por otros objetos opacos (*sacrificio de oclusiones*). |

## D

|  |  |
| --- | --- |
| <b><span id="dependency"></span>Dependencia</b> | Un archivo A utilizado por otro archivo B de forma que el archivo B no funcione según lo previsto cuando falta el archivo A.   Una dependencia de un [paquete](#package) puede ser otro paquete porque hace referencia a un gráfico que contiene, un archivo de imagen, una fuente, etc. Un paquete almacena la ruta de acceso a su dependencia y se genera una advertencia si la dependencia no se encuentra en esa ruta. Las dependencias que faltan también pueden dar como resultado [nodos de instancia fantasma](#ghost-instance-node) en un gráfico. |
| <b><span id="diffuse"></span>Difusión</b> | Canal de un [material](../glossary/glossary.md) definido mediante el modelo [sombreado](#shader) de brillo del Specular PBR. Difusión especifica el color de una superficie cuando está iluminada.   No debe confundirse con [Color base (Albedo)](#base-color). |
| <b><span id="directx"></span>DirectX</b> | Colección de API para gestionar contenido multimedia. Su API 3D, Direct3D, se utiliza ampliamente en el desarrollo de videojuegos y otras industrias 3D.   Direct3D coloca el origen de una textura, es decir, su coordenada (0, 0), en la *parte superior izquierda* (Y-abajo), mientras que la API [OpenGL](#opengl) la coloca en la *parte inferior izquierda* (Y-arriba).   Esto significa que un mapa normal de DirectX tiene un *canal verde invertido* en comparación con OpenGL. De hecho, el canal verde aloja la coordenada Y de los vectores normales. |
| <b><span id="displacement"></span>Desplazamiento</b> | El proceso de mover los [vértices](#vertex) de un modelo 3D, a menudo a lo largo de su [normal](#normal).   El desplazamiento se usa a menudo en combinación con [teselación](#tessellation) y [mapas normales](#normal-map) para modelar detalles más finos en una superficie. |
| <b><span id="dynamic-parameter"></span>Parámetro dinámico</b> | Un parámetro cuyo valor puede cambiar. En otras palabras, cualquier parámetro cuyo valor no sea constante es dinámico.    Esto incluye parámetros expuestos, cualquier parámetro afectado por un parámetro expuesto y cualquier valor de parámetro que se vea afectado por [muestreo en una textura](#texture-sampling).   Contrariamente a [parámetros estáticos](#static-parameter), el valor de los parámetros dinámicos se puede ajustar sobre la marcha después de compilar el gráfico en un archivo SBSAR. |

## E

|  |  |
| --- | --- |
| <b><span id="evaluation"></span>Evaluación</b> | Proceso de resolución de la propagación de datos y parámetros en el gráfico. La evaluación comprueba la validez de un gráfico y sus conexiones, aplica la [herencia](#inheritance) y [cocina](#cooking) el gráfico.   En la vista de gráfico, una conexión se representa con una línea de puntos cuando no se evalúa. La evaluación convierte la conexión en líneas sólidas.    Cada vez que se ajusta un parámetro en un gráfico, el nodo que aloja este parámetro y todos los nodos aguas abajo quedan [invalidados](#invalidation) y deben reevaluarse antes de [procesarse](#rendering). |

## F

|  |  |
| --- | --- |
| <b><span id="filter"></span>Filtro</b> (nodo) | Nodo que aplica una modificación a una imagen (por ejemplo, una deformación) o extrae información de ella (por ejemplo, una máscara). |

## G

|  |  |
| --- | --- |
| <b><span id="ghost-instance-node"></span>Nodo de instancia fantasma</b> | Un [nodo de instancia](#instance-node) que hace referencia a un subgráfico que no se encuentra, es decir, una [dependencia](#dependency) que falta, se carga como un nodo de instancia fantasma.   Los nodos de instancia de Ghost se restauran a su estado esperado resolviendo la dependencia que falta y recargando el [paquete](#package). |
| <b><span id="glossiness"></span>Brillo</b> | Canal de un [material](../glossary/glossary.md) definido mediante el modelo [sombreado](../glossary/glossary.md) de brillo del Specular PBR. El brillo especifica la rugosidad de una superficie, es decir, las variaciones microscópicas de height, también llamadas *microfacetas*.   El brillo alto da como resultado un aspecto suave, mientras que el brillo bajo da como resultado un aspecto mate y rugoso.   Es el inverso de [Rugosidad](#roughness). |

## H

|  |  |
| --- | --- |
| <b><span id="histogram"></span>Histograma (imagen)</b> | En el contexto de una imagen, un histograma representa la población de los valores en un rango dado - a menudo [0, 1].   Esta población se visualiza utilizando barras verticales donde un valor más presente en la imagen resulta en una barra más alta para ese valor. Las barras se distribuyen horizontalmente desde valores bajos (oscuro) a valores altos (brillante).   Los histogramas de imágenes en color suelen superponerse a los histogramas de cada uno de sus canales, normalmente R, G, B. |

## I

|  |  |
| --- | --- |
| <b><span id="inheritance"></span>Herencia</b> | En el contexto de los gráficos de Substance, la herencia describe la propiedad de los nodos que adquieren valores de parámetros de sus nodos ascendentes o de su gráfico principal.   Los parámetros heredados incluyen [resolución](#resolution) ([Tamaño de salida](#output-size)), [profundidad de bits](#bit-depth) ([Formato de salida](#output-format)) y modo [mosaico](#tiling).   Obtenga más información sobre la herencia en esta [página dedicada](../compositing-graphs/inheritance-compositing/inheritance-in-substance-compositing-graphs.md). |
| <b><span id="instance-node"></span>Nodo de instancia</b> | Un nodo de instancia representa un gráfico A en otro gráfico B. En ese caso, el gráfico A puede denominarse [subgráfico](#subgraph) del gráfico B. Cualquier cambio en el gráfico A se propaga a todos los nodos de instancia que lo representan.   El nodo de instancia aplica su propio conjunto de valores para los parámetros de entrada del gráfico A en el contexto del gráfico B. En ese sentido, el gráfico B puede alojar varios nodos de instancia que hagan referencia al gráfico A, pero que pasen valores o texturas diferentes como entradas en el gráfico A.   Todos los nodos de la biblioteca de Designer que no son [nodos atómicos](#atomic-node) son nodos de instancia. |
| <b><span id="invalidation"></span>Invalidación</b> | Proceso que declara que el resultado de un nodo está obsoleto.   Cuando se ajusta un parámetro, el nodo que hospeda este parámetro y todos los nodos aguas abajo quedan invalidados, por lo que es necesario [evaluarlos](#evaluation) y [representarlos](#rendering) de nuevo. |

## M

|  |  |
| --- | --- |
| <b><span id="material"></span>Material</b> | Colección de propiedades y comportamientos de la materia en el espacio, que incluye superficies y volúmenes. El aspecto de una entidad en el espacio 3D se define por su material.   Los materiales pueden definirse de varias maneras y todas las definiciones no admiten todas las propiedades, como la refracción, la anisotropía o el brillo. Un [sombreador](#shader) es una implementación particular de una definición de material.   <b>Importante:</b> El término &quot;material&quot; es un *término general* que se utiliza para referirse a varias cosas, entre ellas:<ul data-preserve-html="true"> <li data-preserve-html="true">El [sombreador](#shader) utilizado para calcular el aspecto de una superficie o volumen;</li> <li data-preserve-html="true">El conjunto de [texturas](#texture) proporcionadas a un sombreado;</li> <li data-preserve-html="true">Un ID de material, que es un atributo de una primitiva 3D utilizada para diferenciar las partes que utilizan materiales diferentes.</li> </ul> |
| <b><span id="mesh"></span>Malla</b> | Un objeto 3D formado por [vértices](#vertex) conectados por aristas para formar polígonos, como triángulos, que a su vez se ensamblan en superficies. Estas superficies pueden estar abiertas o cerradas.   El aspecto de estas superficies está definido por el [material](#material) asignado a ellas. El nivel de detalle de una malla también depende en gran medida de su [número de polímeros](#polycount). |
| <b><span id="metadata"></span>Metadatos</b> | Datos que proporcionan información sobre el propio archivo, su entorno o cualquier cosa relacionada con los datos del archivo.   Entre los metadatos comunes se incluyen el autor del archivo, las fechas de creación y modificación, el copyright y la portada.   En Designer, el contenido de un [paquete](#package) también puede tener metadatos. Por ejemplo, un gráfico Substance que genera un material de tejido puede tener metadatos de las propiedades físicas del tejido. |
| <b><span id="mipmap"></span>Mipmap</b> | Una versión más pequeña de una textura, a menudo calculada automáticamente.   Una textura puede tener una pirámide de versiones más pequeñas de sí misma, que son intercambiables en tiempo de ejecución para que se utilice el tamaño más adecuado para obtener una calidad y un rendimiento óptimos.   Por ejemplo, una textura con detalles de alta frecuencia mostrados en un tamaño más pequeño probablemente producirá artefactos de *moiré*. Además, una textura más grande probablemente incluya más [muestras de textura](#texture-sampling).   El término &#39;mipmap&#39; se origina en la técnica de asignación de MIP, donde MIP significa el latino &#39;*multum in parvo*&#39;, que significa &#39;muchas cosas en un lugar pequeño&#39;. |

## N

|  |  |
| --- | --- |
| <b><span id="node"></span>Nodo</b> | Objeto de un gráfico que realiza cálculos y genera uno o más resultados.   El resultado se controla mediante parámetros de entrada. Estos parámetros se pueden enumerar como controles en el conjunto acoplado Propiedades o como conectores de entrada en el propio nodo.   Hay dos categorías principales de nodos: [nodos atómicos](#atomic-node) y nodos de instancia. |
| <b><span id="noise"></span>Ruido</b> | Imagen no figurativa que representa una distribución aleatoria o pseudoaleatoria de formas y colores. Los ruidos se utilizan a menudo para añadir variación a las superficies o deformaciones.   La biblioteca de nodos de Designer incluye una gran colección de generadores de ruido, como [BnW Spots](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/bnw-spots-2/bnw-spots-2.md), [Clouds](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/clouds-2/clouds-2.md), [Perlin noise](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/perlin-noise/perlin-noise.md) o [Voronoi](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/voronoi/voronoi.md). |
| <b><span id="normal"></span>Normal</b> | En la computación 3D, lo normal de una superficie es un vector [normalizado](#normalization) perpendicular a esa superficie que va desde esa superficie hacia afuera.   Este vector representa la orientación de una superficie en el espacio 3D y se utiliza para [sombreado](#shader) que aparece de acuerdo con las luces de la escena y la perspectiva de la cámara.   Se puede aplicar una textura de [mapa normal](#normal-map) a una superficie para modificar sus normales y agregar detalles. |
| <b><span id="normal-map"></span>Mapa normal</b> | Textura aplicada sobre una superficie para modificar sus normales.   Se utiliza con más frecuencia para fingir detalles que sería ineficiente incluir en la geometría de un modelo. El uso de un mapa de este tipo permite tener normales por texel además de normales por vértice, lo que resulta en más información de la superficie y, por lo tanto, más detalles de la superficie.   Las coordenadas X, Y y Z de los vectores normales se codifican en los canales rojo, verde y azul del mapa respectivamente. En función de la API de gráficos de destino ([DirectX](#directx) o [OpenGL](#opengl)), el canal verde puede estar invertido. |
| <b><span id="normalization"></span>Normalización</b> | Proceso de reasignación de un rango de valores al rango [0, 1], donde el valor de entrada más alto se reasigna a 1.0 y el valor de entrada más bajo se reasigna a 0.0.   Para los vectores, la normalización consiste en ajustar la longitud (o &#39;magnitud&#39;) del vector a un valor de 1,0. |

## O

|  |  |
| --- | --- |
| <b><span id="opengl"></span>OpenGL</b> | Una API de gráficos 3D ampliamente utilizada en el desarrollo de videojuegos y otros sectores 3D.   OpenGL coloca el origen de una textura (es decir, su coordenada (0, 0)) en la *parte inferior izquierda* (Y arriba), mientras que la API [DirectX](#directx) lo coloca en la *parte superior izquierda* (Y abajo).   Esto significa que un mapa normal de OpenGL tiene un *canal verde invertido* en comparación con el DirectX. De hecho, el canal verde aloja la coordenada Y de los vectores normales. |
| <b><span id="openusd"></span>OpenUSD</b> | Consulte [USD](#usd). |
| <b><span id="output-format"></span>Formato de salida</b> | [Parámetro base](#base-parameter) de nodos en un gráfico de Substance que describe la [profundidad de bits](#bit-depth) del nodo. |
| <b><span id="output-size"></span>Tamaño de salida</b> | [Parámetro base](#base-parameter) de nodos en un gráfico de Substance que describe la [resolución](#resolution) del nodo.   Obtenga más información sobre el tamaño de salida en esta [página dedicada](../compositing-graphs/output-size/output-size.md). |

## P

|  |  |
| --- | --- |
| <b><span id="package"></span>Paquete</b> | Un archivo Substance 3D ([SBS](#sbs-file)) se denomina paquete, en el sentido de que es un contenedor de recursos: gráficos, [mapas de bits](#bitmap), [escenas 3D](#three-d-scene), etc. Un paquete también almacena rutas de acceso a sus [dependencias](#dependency), así como [metadatos](#metadata). |
| <b><span id="pattern"></span>Patrón</b> | Una imagen que se debe utilizar como modelo o referencia para producir otra imagen.   En la mayoría de los casos, un patrón es una imagen destinada a ser repetida (por ejemplo, embaldosada, dispersa aleatoriamente o dispuesta de acuerdo con algún conjunto de reglas). |
| <b><span id="pixel-ratio"></span>Proporción de píxeles</b> | Este [parámetro base](#base-parameter) controla la compensación de la proporción de aspecto de la imagen a nivel de píxeles. En otras palabras: si el tamaño en píxeles debe compensarse para conservar una proporción de cuadrados en una imagen no cuadrada.   El parámetro lo utilizan filtros no locales, es decir, filtros que utilizan los valores de los píxeles vecinos para calcular el valor de un píxel. |
| <b><span id="pixel-size"></span>Tamaño de píxel</b> | Este parámetro base define el tamaño horizontal y vertical de un píxel.   Actúa como multiplicador para filtros no locales, es decir, filtros que utilizan los valores de los píxeles vecinos para calcular el valor de un píxel. |
| <b><span id="polycount"></span>Recuento múltiple</b> | La cantidad de polígonos de una [malla](#mesh) 3D. De hecho, polycount es la abreviatura de &#39;número de polígonos&#39;.   Más polígonos pueden modelar detalles más precisos. Las mallas con un polirecuento bajo se denominan &#39;polipoli bajo&#39;, mientras que los polirecuentos más altos se denominan &#39;polipoli alto&#39;. |
| <b><span id="primary-input"></span>Entrada principal</b> | Conector de entrada de un [nodo de instancia](#instance-node) desde el que ese nodo hereda sus valores de [parámetro base](#base-parameter).   La entrada principal se marca con un pequeño punto en su conector y el sufijo &#39;(Principal)&#39; en su etiqueta.   Cuando se usan nodos con más de una entrada, se recomienda *encarecidamente* tener en cuenta cuál de sus entradas es la principal y cómo afecta a la [herencia](#inheritance) en todo el gráfico. |
| <b><span id="procedural"></span>Procedimiento</b> | Característica de un dato o artefacto que se va a crear siguiendo un algoritmo informático, en lugar de hacerlo manualmente.   Designer utiliza un flujo de trabajo procedimental en el que el algoritmo se diseña como un gráfico de nodos.     Los flujos de trabajo procedimentales permiten iteraciones más rápidas porque las variaciones y los ajustes se pueden generar rápidamente modificando el algoritmo y sus parámetros.   Cuando el resultado es enteramente producido por el algoritmo, ese resultado es referido coloquialmente como &#39;100% procedimental&#39;. La generación de procedimientos a veces se acorta a &#39;proc-gen&#39;.   La mayoría de los generadores de la biblioteca de nodos de Designer son 100 % procedimentales, ya que no requieren ninguna imagen de entrada para obtener un resultado. |
| <b><span id="publishing"></span>Publicación (SBSAR)</b> | En Designer, la publicación se refiere a la exportación de un [paquete](#package) como archivo SBSAR que incluye [versiones compiladas](#compilation) de los gráficos, sus recursos ([mapas de bits](#bitmap), fuentes, etc.), sus ajustes preestablecidos y sus [metadatos](#metadata).   El archivo SBSAR resultante se puede distribuir y usar en otras aplicaciones de Substance 3D o aplicaciones de terceros mediante un [complemento de Substance 3D](https://substance3d.adobe.com/plugins/). |

| <b><span id="rendering"></span>Procesando </b> (vista 3D) | Proceso de calcular una imagen según los datos de entrada, mediante un programa como [renderer](#renderer). |

| <b><span id="roughness"></span>Rugosidad</b> | Canal de un [material](../glossary/glossary.md) definido mediante el modelo [sombreado](../glossary/glossary.md) de rugosidad metálica de PBR. La rugosidad especifica la rugosidad de una superficie, es decir, variaciones microscópicas de height, también llamadas *microfacetas*.   Una rugosidad alta da como resultado un aspecto mate, mientras que una rugosidad baja da como resultado un aspecto suave y brillante.   Es el inverso de [Brillo](#glossiness). |

| <b><span id="sbs-file"></span>Archivo SBS</b> | SBS significa &quot;archivo de Substance 3D&quot;. Este archivo se utiliza para almacenar proyectos de Substance 3D Designer. Sus datos utilizan el formato [XML](#xml). Consulte [paquete](#package). |

Este archivo de almacenamiento se utiliza para almacenar gráficos de Substance 3D Designer compilados y los recursos que requieren ([mapas de bits](#bitmap), fuentes, etc.).   SBSAR es el formato de archivo principal que se utiliza para distribuir gráficos de Substance listos para su uso en otras aplicaciones de Substance 3D y complementos de Substance 3D.   Dado que los gráficos almacenados en archivos SBSAR se compilan, no se pueden cargar ni editar en Substance 3D Designer. Sin embargo, los archivos SBSAR se pueden abrir con [7Zip](https://www.7-zip.org/) para recuperar sus parámetros, ajustes preestablecidos y metadatos en un archivo [XML](#xml) incrustado. |
| <span id="sdf"></span><b>SDF</b> | Consulte [Campo Distancia firmada](#signed-distance-field). |
| <b><span id="shader"></span>Shader</b> | Programa que calcula el aspecto de una superficie o volumen según sus propiedades de [material](#material), la luz que recibe y desde dónde se ve. Un sombreado es una implementación particular de una definición de material.   Se pueden proporcionar texturas a un sombreado para impulsar su comportamiento. También se pueden utilizar valores sin procesar. En la [vista 3D](../interface/3d-view/3d-view.md), ve al menú &quot;Materiales&quot; para ver qué sombreador está usando un material en la escena actual. El menú también te permite acceder a las [propiedades de sombreado](../interface/3d-view/3d-view.md) y a las texturas y valores que está usando el sombreado.   &#39;Shader&#39; se usa a veces indistintamente con &#39;[Material](#material)&#39;. |
| <span id="sheen"></span><b>Sheen</b> | Aspecto de brillo o brillo de una tela.   Este término se utiliza ampliamente en la industria textil para describir una propiedad reflectante que añade un brillo de color sutil. |
| <b><span id="signed-distance-field"></span>Campo de distancia firmado (SDF)</b> | <p>Un campo de distancia firmado es una función matemática que define una superficie en el espacio 3D calculando la distancia desde cualquier punto del espacio hasta el punto más cercano de la superficie.</p><p>Obtenga más información sobre el concepto y cómo se utiliza en Designer aquí: [Trabajando con Funciones SDF](../function-graphs/nodes-reference-for-fun/function-node-library/function-nodes-sdf-functions/working-with-sdf-functions.md#what-is-an-sdf-function).</p> |
| <b><span id="spline"></span>Spline</b> | Generalmente, una curva modelada usando una función matemática, que permite dibujar formas limpias y suaves con cualquier resolución. Designer utiliza una aproximación con pérdida codificada en una textura mediante un formato de datos personalizado.   Las splines ofrecen controles intuitivos para la longitud y la trayectoria, incluyen otros datos como el thickness y el height, y proporcionan un acceso sencillo a la distancia y la dirección en cualquier punto a lo largo de ellos.   Estas cualidades las convierten en una poderosa herramienta para dibujar y texturizar. |
| <b><span id="static-parameter"></span>Parámetro estático</b> | Un parámetro cuyo valor no puede cambiar.   Contrariamente a [parámetros dinámicos](#dynamic-parameter), los parámetros estáticos no se pueden cambiar sobre la marcha cuando el gráfico se compila en un archivo SBSAR. Solo se pueden exponer y modificar en Designer cuando se está creando el gráfico.   El modo de vista previa ocultará estos parámetros en algunos casos, ya que su objetivo es hacer coincidir el comportamiento de los archivos SBSAR publicados lo más cerca posible.   Hay disponible una lista de parámetros estáticos [aquí](../compositing-graphs/manage-parameters/exposing-a-parameter/exposing-a-parameter.md). |
| <b><span id="subgraph"></span>Subgráfico</b> | Gráfico utilizado en otro gráfico como [nodo de instancia](#instance-node). |
| <b><span id="substance-engine"></span>Substance Engine</b> | Una tecnología propia desarrollada por el equipo de Substance 3D, encargado de calcular imágenes realizando una gran cantidad de transformaciones, efectos y composición de imágenes de entrada, de manera muy eficiente.   El Substance Engine implementa y calcula los [nodos atómicos](#atomic-node) de Designer.   El motor se implementa a través de diferentes backends, según la plataforma en la que se ejecuta: CPU, GPU y sistema operativo. En Designer, los motores se pueden cambiar yendo a [Herramientas > Cambiar motor](../interface/the-main-toolbar/the-main-toolbar.md).   Algunos backend ofrecen un rendimiento significativamente mejor que otros (por ejemplo, el backend de la GPU es mucho más rápido que el de la CPU) y los resultados pueden ser ligeramente diferentes entre los backend. |
| <b><span id="substance-graph"></span></b><b>Gráfico de Substance</b> (o gráfico de composición de Substance) | Gráfico que genera uno o varios [mapas de bits](#bitmap).   Se puede utilizar un gráfico de Substance para varios fines:  - Producir un conjunto de mapas de bits que son texturas que describen un material;  - Realizar el procesamiento de imágenes en una o más entradas de mapa de bits, como filtro; - Generar ruidos, patrones o datos brutos, como generador. |

## T

|  |  |
| --- | --- |
| <b><span id="tessellation"></span>Mosaico</b> | En los gráficos de ordenador, la teselación es el proceso de subdividir una superficie en más polígonos, a menudo triángulos.   Este proceso se puede realizar en tiempo de ejecución para aumentar dinámicamente la cantidad de polígonos de un modelo 3D, a menudo en combinación con [desplazamiento](#displacement) y [asignaciones normales](#normal-map) para modelar detalles más precisos mediante los polígonos agregados. |
| <b><span id="texel"></span>Texel</b> | La unidad de información de una [textura](#texture), de manera similar a como un píxel es la unidad de información de una imagen. |
| <b><span id="texture"></span>Textura</b> | Una imagen que se usa para representar gráficos, describe las propiedades de [material](#material) de una superficie proporcionando valores a un [sombreador](#shader) y codifica datos sin procesar en sus [texeles](#texel).   Las texturas son objetos que las GPU pueden descomprimir y manipular de forma muy eficaz. En la mayoría de los casos, esta eficiencia requiere texturas para utilizar la potencia de dos resoluciones: por ejemplo, 1024x1024, 4096x4096, 512x256, etc. |
| <b><span id="texture-sampling"></span>Muestreo de texturas</b> | Adquiriendo el valor de una [textura](#texture) en una ubicación específica.   Algunos algoritmos requieren que se realicen muchas muestras para comparar valores, promediarlos u otras operaciones.   Si una muestra no se realiza exactamente en el centro de un píxel, hay dos opciones en Designer para el valor que debe adquirirse:<ul data-preserve-html="true"> <li data-preserve-html="true"><b>Más cercano:</b> Valor del píxel más cercano según su centro</li> <li data-preserve-html="true"><b>Filtrado bilineal:</b> Valor de la interpolación entre los píxeles adyacentes horizontal y verticalmente, donde los píxeles más cercanos tienen más peso.</li> </ul> |
| <b><span id="tiling"></span>Mosaico</b> | La repetición de una imagen horizontal, verticalmente, o ambas cosas, sin costuras visibles o discontinuidad visual.   Designer ofrece muchos [nodos](#node) que generan [ruidos](#noise) o [patrones](#pattern) que forman el mosaico. Del mismo modo, muchos nodos [filter](#filter) están diseñados para procesar imágenes a la vez que se conserva el mosaico. |

## U

|  |  |
| --- | --- |
| <b><span id="usage"></span>Uso (salida)</b> | En los gráficos de Substance, un uso es un atributo de un nodo [Output](../compositing-graphs/nodes-reference-for-com/atomic-nodes/output/output.md) que se utiliza para que la aplicación sepa cómo conectar una [textura](#texture) al [sombreador](#shader) en la [vista 3D](../interface/3d-view/3d-view.md).   Al aplicar un gráfico de Substance a la vista 3D, todas las salidas se conectan al sombreado en función de los usos coincidentes. Es decir, &#39;basecolor&#39; a &#39;basecolor&#39;, &#39;rugosidad&#39; a &#39;rugosidad&#39;, etc.   Los usos también se utilizan para hacer coincidir los conectores cuando se usan los modos de creación de vínculos [Material&#39; y &#39;Compact Material&#39;](../interface/the-graph-view/link-creation-modes/link-creation-modes.md). |
| <b><span id="udim"></span>UDIM</b> (mosaicos UV) | Estándar para dividir el espacio [UV](#uv) en mosaicos con un identificador numérico único, que permite asignar una textura diferente a cada mosaico.   Los flujos de trabajo UDIM son habituales en las canalizaciones de VFX, donde los activos de alta fidelidad requieren tanto detalle que se requieren varias texturas de alta resolución. En ese caso, los [UV](#uv) del activo se organizan en varios UDIM (o mosaicos UV).   Designer admite flujos de trabajo UDIM y puede asignar un gráfico de Substance diferente por UDIM. |
| <b><span id="usd"></span>USD</b> (o OpenUSD) | El [Universal Scene Description](https://openusd.org/release/index.html) (USD) es un formato de descripción de escena 3D creado por Pixar, creado para la interoperabilidad y el intercambio de datos entre aplicaciones y plataformas.   Los archivos USD incluyen la definición de los datos utilizados en una escena, así como la composición de esa escena y todo lo que implica: modelos, materiales, cámaras, animaciones, simulaciones, etc. Un archivo USD puede incluir cualquier tipo de datos, siempre que la aplicación tenga acceso al plugin USD que le permita leer y usar esos datos correctamente.   Adobe está [involucrado en Alliance for OpenUSD](https://blog.adobe.com/en/publish/2023/08/01/powering-3d-interoperability-continued-collaboration-through-openusd), un consorcio de actores de la industria 3D que contribuyen activamente al desarrollo y estandarización del formato. |
| <b><span id="uv"></span>UV</b> | Los UV son una representación de un modelo 3D en un espacio 2D. Se utilizan para asignar imágenes 2D del espacio 2D en la superficie del modelo en el espacio 3D.   El proceso de creación de los UV se describe a menudo como el corte de dobleces en el modelo para desplegarlo y aplanarlo. |
